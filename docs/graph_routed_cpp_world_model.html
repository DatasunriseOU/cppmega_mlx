Graph-Routed C/C++ World Model

Cppmega world models are not generic language models. Every sample carries graph routes and domain-special-token-wrapped C++/build/shell/diagnostic streams so sparse attention is selected from compiler and environment evidence.

Docs-only design contract

Mandatory Surfaces

The token stream is a typed transcript. Source is wrapped with code markers; build, shell, tool, and diagnostic spans are represented with tool/result or diagnostic wrappers. The current local anchors are the stable special-token contract, C++ tokenizer, and platform-context renderer.

Dense text-only experiments can remain baselines, but they are not cppmega world models unless both mandatory surfaces are present.

Invariant

Graph bias must be applied before top-k selection. Route metadata is not optional retrieval context and must not be replaced by prose.

Route Families

Implemented

call

Caller/callee or use-to-definition call structure, currently routed through graph packets and sidecars.

Implemented

type

Token or symbol to type relation. Required by type-aware probe requirements and graph routes.

Promote

def_use

Value-origin and data-flow relation. Present in packet semantics and graph examples, should become a route family.

Design target

build_error

Compiler, linker, test, and build-spec failures connected to source spans, symbols, and build commands.

DSA, Top-k, And Loss

The graph router builds a relation/block bias S_graph. The indexer applies I_final = I_neural + beta * S_graph before top-k selection. Losses combine dense-attention KL warm-up, graph edge BCE, coverage hinge loss, recall-at-k, and top-k overlap metrics.

Layer Contract Live source
Graph router Fixed route topology with learned relation weights; fail loudly on missing required relations code_graph_routes.py
Indexer loss Apply graph bias before top-k and supervise graph coverage indexer_losses.py
MLX sparse attention Consume sparse top-k indices; invalid slots use -1 sparse_mla.py
Megatron bridge Avoid full index-score materialization and carry graph sidecars into the batch dsa_indexer_fused_patch.py, structure_dataset_patch.py

LoopWM Stable Loop

observe(domain stream + graph routes)
  -> predict constrained edit/action
  -> validate tokenizer, syntax, graph alignment, build/test
  -> convert failures to diagnostics and build_error routes
  -> re-index source/build state
  -> next TrajectoryPacket transition

The local trajectory contract is in trajectory_packet.py. LoopWM is used as an architectural direction: reuse a stable transition loop over typed state and refresh routes on each step, instead of letting untyped text rollouts drift away from buildable C++.

Constrained Valid-Code Generation

  • Code is generated only inside source wrappers.
  • Build, shell, and diagnostic content is generated only inside its domain wrapper.
  • Generated edits must match token ranges and chunk metadata before entering the next state.
  • Syntax, build, and test failures become diagnostic streams plus graph routes.
  • Strict verification should fail closed, matching the build-spec diagnostics pattern.
